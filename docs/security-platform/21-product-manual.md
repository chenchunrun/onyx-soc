# Onyx 智能安全底座产品说明书

## 1. 产品定位

Onyx 智能安全底座是一套面向企业安全运营、漏洞管理、威胁研判和应急响应的安全智能平台。平台以 Onyx 企业知识检索与大模型编排能力为基础，将安全智能体、安全 Skill、内部知识库、威胁情报、资产上下文和安全工具网关融合到统一工作台中，帮助安全团队完成从“提出安全问题”到“形成研判结论和处置建议”的闭环。

产品核心目标不是替代安全人员，而是将重复的信息检索、情报归并、影响分析、工具调用和报告生成自动化，使安全人员把精力集中在判断、授权和处置决策上。


## 2. 适用对象

- 安全运营中心（SOC）：用于告警研判、事件分流、威胁情报查询和处置建议生成。
- 漏洞管理团队：用于 CVE 影响评估、补丁优先级排序、缓解措施建议和资产影响分析。
- 应急响应团队：用于事件初判、影响面梳理、遏制步骤规划和复盘材料生成。
- 安全管理者：用于快速了解风险态势、处置进展、能力覆盖范围和平台运行状态。
- 平台管理员：用于配置安全智能体、Skill、工具集成、部署模式和运行时权限边界。


## 3. 核心能力

### 3.1 安全智能体

平台内置面向安全场景的专用智能体，每个智能体包含独立的提示词、能力边界、关联 Skill 和推荐工具。

- 漏洞评估专家：负责漏洞影响评估、利用条件分析、补丁优先级和缓解建议。
- 恶意软件分析师：负责样本分析、可疑行为解释、IOC 提取和家族线索归纳。
- 安全事件分析师：负责告警 triage、事件上下文整理和初步处置建议。
- 应急响应指挥官：负责处置流程编排、影响控制、升级建议和复盘框架。
- 威胁狩猎工程师：负责威胁假设生成、查询思路设计和线索关联。
- 合规审计员：负责控制项解释、证据归档建议和审计差距梳理。
- 检测工程师：负责检测规则设计、覆盖面分析和误报优化建议。

### 3.2 安全 Skill

安全 Skill 是围绕具体安全任务封装的运行时能力。平台会根据用户输入自动识别可能匹配的 Skill，并在输入框中展示建议路由、置信度、推荐智能体和匹配能力。

典型 Skill 包括：

- 资产发现：面向授权目标的资产上下文查询、外部暴露面分析和资产清点。
- 漏洞研究：围绕 CVE、厂商公告、漏洞利用条件和修复建议进行综合研判。
- SCA 分析：面向组件、依赖和供应链风险进行识别与解释。
- 安全告警分析：结合告警字段、IOC、资产上下文和历史知识进行研判。

受限 Skill 默认不自动启用。用户需要显式选择启用，避免未授权的扫描、外部访问或高风险动作被自动触发。

### 3.3 内部知识与文件检索

平台可以检索企业内部文档、威胁情报、上传文件、知识库材料和安全报告，并将结果作为回答依据。

能力特点：

- 支持自然语言查询内部安全文档。
- 支持围绕 CVE、资产、告警、产品或处置流程进行语义检索。
- 支持引用来源，便于安全人员追溯依据。
- 针对内部文件和单条情报记录做了性能优化，减少无效上下文扩展和长时间等待。

### 3.4 工具编排与安全集成

平台支持通过 OpenAPI / 工具网关接入外部安全系统，例如：

- 资产管理 / CMDB
- 威胁情报平台
- SIEM 查询
- EDR 响应动作
- 工单系统
- 安全告警平台

工具调用结果会回传给大模型，用于生成下一步判断。若上游服务不可用，平台会返回可解释的工具结果，而不是直接中断会话。

### 3.5 任务路由

平台提供安全任务路由能力，根据用户输入识别任务类型，并推荐合适的智能体、Skill 和处置路径。

示例：

- “评估 CVE-2025-12480 的影响范围”会路由到漏洞评估专家和漏洞研究能力。
- “对 127.0.0.1 做资产发现测试”会路由到资产发现 Skill。
- “分析这条告警是否需要升级”会路由到安全事件分析师和告警研判流程。


## 4. 典型使用场景

### 4.1 漏洞影响评估

用户输入 CVE 编号、厂商公告或漏洞描述后，平台会：

1. 检索内部漏洞情报和相关文档。
2. 汇总漏洞严重性、利用状态、影响范围和修复建议。
3. 判断补丁优先级和临时缓解措施。
4. 输出面向安全运营或管理层的评估报告。

适合场景：

- 新漏洞爆发后的快速研判。
- 补丁优先级排序。
- 与资产清单联动判断受影响系统。

### 4.2 资产发现与暴露面分析

用户输入目标 IP、域名、URL 或资产名称后，平台会提示是否启用资产发现 Skill。启用后可调用资产上下文或攻击面相关工具。

平台会输出：

- 调用状态。
- 资产上下文。
- 可能的暴露面。
- 后续核查建议。

如果上游资产服务不可用，平台会明确提示“上游服务不可用”，并给出下一步排查建议。

### 4.3 告警研判

用户粘贴告警摘要、IOC、进程信息、网络连接或日志片段后，平台会：

1. 抽取关键实体。
2. 查询相关内部知识和威胁情报。
3. 判断告警可信度、风险级别和可能攻击路径。
4. 输出处置建议、升级条件和证据清单。

### 4.4 恶意软件分析

用户上传或描述样本行为后，平台可以辅助：

- 提取 IOC。
- 分析可疑行为。
- 归纳可能的攻击阶段。
- 生成隔离、阻断和后续取证建议。

### 4.5 应急响应协同

在事件处理中，平台可以生成：

- 事件时间线。
- 影响范围判断。
- 遏制步骤。
- 沟通材料。
- 复盘报告结构。


## 5. 用户界面说明

### 5.1 首页输入区

输入区支持自然语言安全任务。系统会根据内容展示：

- 推荐路由。
- 推荐智能体。
- 匹配 Skill。
- 置信度。
- 是否可切换智能体。
- 是否可启用匹配 Skill。

### 5.2 智能体页面

智能体页面展示当前安全角色、默认能力、关联 Skill 和运行时能力状态。

用户可以：

- 查看 Runtime Profile。
- 了解当前智能体适合处理的任务。
- 对受限 Skill 做显式启用。
- 在当前智能体上下文中发起安全分析。

### 5.3 Runtime Skill Activation

Runtime Skill Activation 用于控制受限 Skill 的启用状态。设计原则是：

- 默认关闭高风险能力。
- 用户按消息粒度启用。
- 展示 Skill 的适用范围、策略标签和限制条件。
- 避免未经确认的扫描、资产发现或外部系统动作。

### 5.4 管理端安全平台页面

管理端用于平台管理员查看或维护：

- 安全平台能力概览。
- 工具集成状态。
- 任务路由预览。
- Skill / agent 配置状态。
- 部署与健康检查信息。


## 6. 安全与治理机制

### 6.1 权限边界

平台遵循最小权限原则：

- 受限 Skill 默认不启用。
- 外部工具调用需要明确配置。
- 高风险动作应通过网关、审批或策略控制。
- 工具调用失败时应降级为可解释结果，不直接中断会话。

### 6.2 数据边界

平台主要处理以下数据：

- 企业内部文档和知识库。
- 安全告警和 IOC。
- 漏洞情报。
- 用户上传文件。
- 工具调用返回的安全上下文。

部署时应根据企业要求配置数据保留、访问控制、日志脱敏和密钥管理。

### 6.3 审计与可追溯

建议在生产环境开启：

- 工具调用审计。
- 用户查询历史审计。
- 管理端配置变更审计。
- 外部工具网关访问日志。
- 安全 Skill 启用记录。


## 7. 性能与稳定性

平台针对安全问答中的常见慢路径做了优化：

- 限制进入 LLM 文档筛选的候选数量，降低长尾延迟。
- 对内部文件和单条情报记录跳过无效上下文扩展。
- 对上下文扩展并发做限流，避免工具扇出过大。
- 对模型 tokenizer 加入离线加载和 fallback，避免启动或运行时网络阻塞。
- 对外部工具不可达场景返回可解释结果，而不是抛出未预期异常。

当前实测结果显示，典型内部漏洞情报查询的搜索工具耗时可以控制在十几秒级，具体端到端时间仍受模型响应速度、工具链路和回答长度影响。


## 8. 部署形态

平台支持以下部署形态：

- 本地 Demo：适合功能演示、开发调试和离线评估。
- 网关模式：通过统一安全工具网关访问外部系统。
- 生产自托管：部署到企业私有环境，接入企业身份、权限、日志和安全工具。
- 多租户 / 企业版部署：结合 RBAC、SCIM、服务账号、密钥加密和自定义部署策略。

部署前需要确认：

- 数据库、Redis、Vespa / OpenSearch、模型服务和 Web 服务健康。
- 安全工具网关地址可达。
- 必要密钥通过 Secret 管理机制注入。
- Agent、Skill、工具配置与当前部署 profile 匹配。


## 9. 使用限制

- 平台输出为辅助研判结果，不能替代安全人员的最终判断。
- 主动扫描、资产发现、阻断、隔离、工单创建等动作应受授权和审批控制。
- 如果外部工具网关不可用，平台只能返回降级信息，不能获取实时外部上下文。
- 大模型可能产生不完整或错误推断，关键结论应结合来源引用和人工复核。
- 对生产环境的高风险操作应通过专门的审批流、审计和回滚机制执行。


## 10. 验收建议

建议用以下场景验证产品可用性：

- 普通安全问答：询问某类漏洞、攻击技术或处置流程。
- 内部文件查询：查询已入库的 CVE、威胁情报或安全报告。
- 漏洞评估专家：输入 CVE 编号，检查影响评估和补丁优先级输出。
- 资产发现 Skill：输入授权测试目标，检查 Skill 启用、工具调用和降级结果。
- 工具不可达场景：关闭或断开上游工具服务，确认平台返回可解释错误。
- 管理端预览：检查安全任务路由、工具状态和 Skill 配置是否符合预期。


## 11. 常见问题

### 11.1 为什么有些 Skill 默认关闭？

资产发现、扫描、响应动作等能力可能涉及外部系统访问或高风险操作，因此默认关闭。用户需要在具体消息中显式启用，平台才会把该能力纳入本次任务。

### 11.2 为什么工具调用失败但回答仍然继续？

这是预期行为。平台会把上游不可达、参数不合法或权限不足等情况转换为可解释的工具结果，让模型基于失败原因给出下一步建议，而不是直接中断会话。

### 11.3 为什么同样的问题耗时不同？

耗时主要受检索候选数量、模型响应速度、是否调用工具、是否启用 Skill、回答长度和上游系统可用性影响。内部文件和单条情报查询已做专门优化，但复杂 agent 工作流仍可能需要多轮工具调用。

### 11.4 如何判断结果是否可信？

优先查看回答中的来源引用、工具调用状态、证据链和不确定性说明。对于漏洞处置、阻断、隔离和生产变更，应进行人工复核。


## 12. 后续产品化方向

- 增强安全任务路由的可配置性和可解释性。
- 为高风险 Skill 增加审批流和策略中心。
- 增加更多安全工具连接器和统一工具健康检查。
- 提供更完整的安全任务看板、SLA、工单联动和审计报表。
- 支持企业级知识治理、情报生命周期管理和自动过期机制。
- 优化 agent 工作流的长任务体验、进度展示和可中断能力。
