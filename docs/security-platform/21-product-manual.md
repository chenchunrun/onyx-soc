# CMSOC 智能安全底座产品说明书

## 1. 产品定位

CMSOC 智能安全底座是一套面向企业安全运营、漏洞管理、威胁研判和应急响应的安全智能平台。平台以企业知识检索与大模型编排能力为基础，将安全智能体、安全 Skill、内部知识库、威胁情报、资产上下文和安全工具网关融合到统一工作台中，帮助安全团队完成从“提出安全问题”到“形成研判结论和处置建议”的闭环。

产品核心目标不是替代安全人员，而是将重复的信息检索、情报归并、影响分析、工具调用和报告生成自动化，使安全人员把精力集中在判断、授权和处置决策上。


## 2. 适用对象

- 安全运营中心（SOC）：用于告警研判、事件分流、威胁情报查询和处置建议生成。
- 漏洞管理团队：用于 CVE 影响评估、补丁优先级排序、缓解措施建议和资产影响分析。
- 应急响应团队：用于事件初判、影响面梳理、遏制步骤规划和复盘材料生成。
- 安全管理者：用于快速了解风险态势、处置进展、能力覆盖范围和平台运行状态。
- 平台管理员：用于配置安全智能体、Skill、工具集成、部署模式和运行时权限边界。


## 3. 核心能力

### 3.1 安全智能体

平台内置面向安全场景的专用智能体，每个智能体包含独立的提示词、能力边界、关联 Skill 和推荐工具。

- 漏洞评估专家：负责漏洞影响评估、利用条件分析、补丁优先级和缓解建议。
- 恶意软件分析师：负责样本分析、可疑行为解释、IOC 提取和家族线索归纳。
- 安全事件分析师：负责告警 triage、事件上下文整理和初步处置建议。
- 应急响应指挥官：负责处置流程编排、影响控制、升级建议和复盘框架。
- 威胁狩猎工程师：负责威胁假设生成、查询思路设计和线索关联。
- 合规审计员：负责控制项解释、证据归档建议和审计差距梳理。
- 检测工程师：负责检测规则设计、覆盖面分析和误报优化建议。

### 3.2 安全 Skill

安全 Skill 是围绕具体安全任务封装的运行时能力。平台会根据用户输入自动识别可能匹配的 Skill，并在输入框中展示建议路由、置信度、推荐智能体和匹配能力。

典型 Skill 包括：

- 资产发现：面向授权目标的资产上下文查询、外部暴露面分析和资产清点。
- 漏洞研究：围绕 CVE、厂商公告、漏洞利用条件和修复建议进行综合研判。
- SCA 分析：面向组件、依赖和供应链风险进行识别与解释。
- 安全告警分析：结合告警字段、IOC、资产上下文和历史知识进行研判。

受限 Skill 默认不自动启用。用户需要显式选择启用，避免未授权的扫描、外部访问或高风险动作被自动触发。

### 3.3 内部知识与文件检索

平台可以检索企业内部文档、威胁情报、上传文件、知识库材料和安全报告，并将结果作为回答依据。

能力特点：

- 支持自然语言查询内部安全文档。
- 支持围绕 CVE、资产、告警、产品或处置流程进行语义检索。
- 支持引用来源，便于安全人员追溯依据。
- 针对内部文件和单条情报记录做了性能优化，减少无效上下文扩展和长时间等待。

### 3.4 工具编排与安全集成

平台支持通过 OpenAPI / 工具网关接入外部安全系统，例如：

- 资产管理 / CMDB
- 威胁情报平台
- SIEM 查询
- EDR 响应动作
- 工单系统
- 安全告警平台

工具调用结果会回传给大模型，用于生成下一步判断。平台内置调用连续性保障机制，可在外部系统状态波动时提供可解释反馈，确保任务流程连续。

### 3.5 任务路由

平台提供安全任务路由能力，根据用户输入识别任务类型，并推荐合适的智能体、Skill 和处置路径。

示例：

- “评估 CVE-2025-12480 的影响范围”会路由到漏洞评估专家和漏洞研究能力。
- “对 127.0.0.1 做资产发现测试”会路由到资产发现 Skill。
- “分析这条告警是否需要升级”会路由到安全事件分析师和告警研判流程。


## 4. 典型使用场景

### 4.1 漏洞影响评估

用户输入 CVE 编号、厂商公告或漏洞描述后，平台会：

1. 检索内部漏洞情报和相关文档。
2. 汇总漏洞严重性、利用状态、影响范围和修复建议。
3. 判断补丁优先级和临时缓解措施。
4. 输出面向安全运营或管理层的评估报告。

适合场景：

- 新漏洞爆发后的快速研判。
- 补丁优先级排序。
- 与资产清单联动判断受影响系统。

### 4.2 资产发现与暴露面分析

用户输入目标 IP、域名、URL 或资产名称后，平台会提示是否启用资产发现 Skill。启用后可调用资产上下文或攻击面相关工具。

平台会输出：

- 调用状态。
- 资产上下文。
- 可能的暴露面。
- 后续核查建议。

当资产数据源存在波动时，平台会提供清晰状态说明与后续建议，帮助团队保持研判节奏。

### 4.3 告警研判

用户粘贴告警摘要、IOC、进程信息、网络连接或日志片段后，平台会：

1. 抽取关键实体。
2. 查询相关内部知识和威胁情报。
3. 判断告警可信度、风险级别和可能攻击路径。
4. 输出处置建议、升级条件和证据清单。

### 4.4 恶意软件分析

用户上传或描述样本行为后，平台可以辅助：

- 提取 IOC。
- 分析可疑行为。
- 归纳可能的攻击阶段。
- 生成隔离、阻断和后续取证建议。

### 4.5 应急响应协同

在事件处理中，平台可以生成：

- 事件时间线。
- 影响范围判断。
- 遏制步骤。
- 沟通材料。
- 复盘报告结构。


## 5. 用户界面说明

### 5.1 首页输入区

输入区支持自然语言安全任务。系统会根据内容展示：

- 推荐路由。
- 推荐智能体。
- 匹配 Skill。
- 置信度。
- 是否可切换智能体。
- 是否可启用匹配 Skill。

### 5.2 智能体页面

智能体页面展示当前安全角色、默认能力、关联 Skill 和运行时能力状态。

用户可以：

- 查看 Runtime Profile。
- 了解当前智能体适合处理的任务。
- 对受限 Skill 做显式启用。
- 在当前智能体上下文中发起安全分析。

### 5.3 Runtime Skill Activation

Runtime Skill Activation 用于控制受限 Skill 的启用状态。设计原则是：

- 默认关闭高风险能力。
- 用户按消息粒度启用。
- 展示 Skill 的适用范围、策略标签和限制条件。
- 避免未经确认的扫描、资产发现或外部系统动作。

### 5.4 管理端安全平台页面

管理端用于平台管理员查看或维护：

- 安全平台能力概览。
- 工具集成状态。
- 任务路由预览。
- Skill / agent 配置状态。
- 部署与健康检查信息。


## 6. 安全与治理机制

### 6.1 权限边界

平台遵循最小权限原则：

- 受限 Skill 默认不启用。
- 外部工具调用需要明确配置。
- 高风险动作应通过网关、审批或策略控制。
- 工具链路具备连续性保护能力，确保分析任务保持可追踪、可恢复。

### 6.2 数据边界

平台主要处理以下数据：

- 企业内部文档和知识库。
- 安全告警和 IOC。
- 漏洞情报。
- 用户上传文件。
- 工具调用返回的安全上下文。

部署时应根据企业要求配置数据保留、访问控制、日志脱敏和密钥管理。

### 6.3 审计与可追溯

建议在生产环境开启：

- 工具调用审计。
- 用户查询历史审计。
- 管理端配置变更审计。
- 外部工具网关访问日志。
- 安全 Skill 启用记录。


## 7. 性能与稳定性

平台针对安全问答中的常见慢路径做了优化：

- 限制进入 LLM 文档筛选的候选数量，降低长尾延迟。
- 对内部文件和单条情报记录跳过无效上下文扩展。
- 对上下文扩展并发做限流，避免工具扇出过大。
- 对模型 tokenizer 加入离线加载和 fallback，避免启动或运行时网络阻塞。
- 对外部工具不可达场景返回可解释结果，而不是抛出未预期异常。

当前实测结果显示，典型内部漏洞情报查询的搜索工具耗时可以控制在十几秒级，具体端到端时间仍受模型响应速度、工具链路和回答长度影响。


## 8. 部署形态

平台支持以下部署形态：

- 本地 Demo：适合功能演示、开发调试和离线评估。
- 网关模式：通过统一安全工具网关访问外部系统。
- 生产自托管：部署到企业私有环境，接入企业身份、权限、日志和安全工具。
- 多租户 / 企业版部署：结合 RBAC、SCIM、服务账号、密钥加密和自定义部署策略。

部署前需要确认：

- 数据库、Redis、Vespa / OpenSearch、模型服务和 Web 服务健康。
- 安全工具网关地址可达。
- 必要密钥通过 Secret 管理机制注入。
- Agent、Skill、工具配置与当前部署 profile 匹配。


## 9. 产品价值承诺

CMSOC 面向企业安全团队提供以下核心价值承诺：

- 更快响应：将“人工多系统检索 + 汇总”缩短为一次对话式任务编排。
- 更稳决策：基于来源可追溯的证据链输出结论和建议，降低信息噪声。
- 更高覆盖：通过多智能体 + 多 Skill + 多工具联动覆盖漏洞、告警、威胁和应急场景。
- 更易落地：支持从本地 PoC 到企业生产部署的平滑演进。
- 更可治理：支持权限边界、审计留痕、审批策略与企业安全制度对齐。


## 10. 上线与验收建议

建议按“三阶段”推动上线，确保推广效果和交付质量：

1. 场景试点（1-2 周）  
围绕 2-3 个高频场景试跑，例如 CVE 评估、告警研判、资产上下文查询。

2. 业务扩展（2-4 周）  
扩展到更多安全角色与团队，接入核心工具链（CMDB/SIEM/EDR/工单）。

3. 生产运营（持续）  
纳入日常安全运营流程，建立指标看板和复盘机制。

推荐验收指标：

- 时效指标：平均研判时长、首响时间、处置建议生成时间。
- 质量指标：结论可追溯率、误判率、人工复核通过率。
- 运营指标：智能体使用覆盖率、场景复用率、工具调用成功率。


## 11. 对外推广常见问答

### 11.1 CMSOC 与普通大模型问答的区别是什么？

CMSOC 不是单一问答机器人，而是“安全智能体 + 安全 Skill + 工具编排 + 企业知识”的完整平台，能够直接对接安全运营流程并输出可执行建议。

### 11.2 CMSOC 是否支持企业现有安全体系？

支持。平台可与企业常见安全系统集成，并支持权限控制、审计留痕与分阶段上线，便于与现有流程并行运行。

### 11.3 CMSOC 的部署方式是否灵活？

支持本地演示、网关模式与企业私有化部署。可根据组织规模、合规要求和网络环境选择适配方案。

### 11.4 CMSOC 的推广切入点建议是什么？

建议优先从“高频、重复、耗时”的安全任务切入，例如漏洞通报评估、告警初筛与应急信息汇总，通常更容易形成可量化的业务收益。


## 12. 产品演进方向

- 智能路由增强：提升跨场景任务识别精度和执行路径推荐能力。
- 工具生态扩展：增加更多安全工具连接器与统一接入规范。
- 安全运营看板：完善 SLA、闭环率、效率提升等运营指标可视化。
- 协同闭环强化：增强与工单、审批、通知系统的自动化联动能力。
- 企业级治理：持续强化策略控制、审计能力与组织级配置管理能力。
