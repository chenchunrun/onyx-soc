## 1. 应急响应概述

### 1.1 目的

本手册旨在规范网络安全事件的应急响应流程，确保在发生安全事件时能够快速、有序、有效地进行处置，最大限度地减少损失和影响。

### 1.2 适用范围

- 恶意代码感染事件
- 网络入侵事件
- 数据泄露事件
- 拒绝服务攻击
- 内部威胁事件
- 第三方服务安全事件
- 其他影响信息系统安全的突发事件

### 1.3 应急响应团队

| 角色 | 职责 | 联系方式 |
|------|------|----------|
| 应急响应指挥官 | 统筹指挥、决策、资源协调 | 见内部通讯录 |
| 安全分析师 | 事件分析、取证、溯源 | 见内部通讯录 |
| 系统管理员 | 系统隔离、恢复、重建 | 见内部通讯录 |
| 网络安全工程师 | 网络隔离、流量分析、防火墙操作 | 见内部通讯录 |
| 法务/合规顾问 | 法律风险评估、监管报告 | 见内部通讯录 |
| 公关/品牌顾问 | 对外沟通、舆情管理 | 见内部通讯录 |

## 2. 应急响应流程

### 2.1 阶段一：准备（Preparation）

#### 2.1.1 日常准备工作

**人员准备：**
- 维护应急响应联系人列表（每月更新）
- 确保关键人员7×24小时可联系
- 建立备用联系方式（防主渠道失效）
- 定期参加应急响应培训和演练

**工具准备：**
- 取证工具包（内存镜像、磁盘镜像、日志采集）
- 隔离工具（ACL管理脚本、网络隔离方案）
- 通信工具（加密通信渠道、事件协同平台）
- 文档模板（事件记录表、时间线模板）

**文档准备：**
- 当前系统架构图
- 网络拓扑图（含VLAN、ACL信息）
- 资产清单（IP、主机名、用途、负责人）
- 备份清单（备份频率、存放位置、恢复测试记录）

#### 2.1.2 应急响应启动检查清单

- [ ] 确认事件真实性（排除误报）
- [ ] 创建事件记录（INC-YYYYMMDD-NNN）
- [ ] 确定事件级别
- [ ] 通知应急响应团队
- [ ] 开通事件通信渠道（专用IM频道/电话桥）
- [ ] 分配事件指挥官
- [ ] 记录开始时间

### 2.2 阶段二：检测与分析（Detection & Analysis）

#### 2.2.1 告警验证

**验证步骤：**

1. **确认告警来源**
   - 查看SIEM/EDR/XDR告警详情
   - 记录告警时间、告警名称、告警规则ID
   - 确认告警置信度

2. **交叉验证**
   - 查看同时间窗口其他相关告警
   - 对比系统正常基线
   - 检查网络流量是否异常
   - 确认是否有用户报告

3. **初步影响评估**
   - 确认受影响系统范围
   - 确认涉及账户和权限级别
   - 确认是否涉及敏感数据
   - 评估业务影响

#### 2.2.2 事件分析

**日志采集范围：**

| 系统类型 | 采集日志 | 采集时长 |
|----------|----------|----------|
| Windows服务器 | Security、System、Application、PowerShell | 事件前7天至恢复后 |
| Linux服务器 | auth.log、syslog、audit.log、bash_history | 事件前7天至恢复后 |
| 网络设备 | 防火墙、交换机、路由器日志 | 事件前30天至恢复后 |
| 数据库 | 审计日志、错误日志、慢查询日志 | 事件前7天至恢复后 |
| 应用系统 | 访问日志、错误日志、安全日志 | 事件前7天至恢复后 |
| 云平台 | CloudTrail/VPC Flow/CloudWatch | 事件前30天至恢复后 |

**分析重点：**

1. **时间线重建**
   - 首次入侵时间（Earliest Compromise）
   - 攻击者活动路径
   - 横向移动时间点
   - 数据访问/外泄时间

2. **攻击痕迹识别**
   - 新增/修改的用户账户
   - 新增的计划任务/服务
   - 异常进程和网络连接
   - 注册表修改（Windows）
   - SSH密钥和cron任务（Linux）
   - 异常认证日志

3. **影响范围确定**
   - 所有被入侵的主机列表
   - 所有被泄露的账户
   - 被访问/窃取的数据类型和数量
   - 被修改或删除的文件

#### 2.2.3 证据保全

**证据保全优先级（按易失性排序）：**

1. **内存数据**（最高优先级，关闭系统即丢失）
   - 使用 DumpIt、Magnet RAM Capture 等工具
   - 记录采集时间、采集人、系统时间

2. **网络连接**
   - `netstat -ano > network_connections.txt`
   - 抓包：tcpdump -i any -w capture.pcap

3. **运行进程**
   - `ps auxww > running_processes.txt`
   - Windows: `tasklist /v > tasklist.txt`

4. **磁盘镜像**（需要使用写保护设备）
   - FTK Imager、dd、Guymager
   - 计算SHA-256哈希值

5. **日志文件**
   - 完整导出所有相关日志
   - 确认日志完整性（未篡改）

**证据链管理：**
- 记录每个证据的采集人、采集时间、存放位置
- 所有证据使用只读介质存储
- 计算并记录哈希值用于完整性验证
- 证据移交需双方签字确认

### 2.3 阶段三：遏制（Containment）

#### 2.3.1 遏制策略原则

**原则一：证据优先**
- 在执行任何可能破坏证据的操作前，先完成证据采集
- 如果无法先采集（如系统正在被攻击），记录此决策原因

**原则二：平衡风险**
- 短期遏制措施（快速止血）vs 长期遏制措施（彻底消除）
- 避免遏制措施本身造成业务中断

**原则三：范围控制**
- 遏制范围宁大勿小
- 随着调查深入可缩小范围

#### 2.3.2 短期遏制措施

**立即执行（0-30分钟）：**

| 操作 | 适用场景 | 执行人 | 风险提示 |
|------|----------|--------|----------|
| 断网隔离 | 确认被控主机 | 系统管理员 | 可能中断业务，需评估 |
| 禁用账户 | 确认被入侵账户 | AD管理员 | 影响用户正常业务 |
| 封锁IP/域名 | 确认恶意IOC | 网络安全工程师 | 可能影响正常服务 |
| 关闭服务 | 确认恶意服务 | 系统管理员 | 服务中断，需通知业务 |

**隔离方式选择：**

| 隔离方式 | 适用场景 | 优点 | 缺点 |
|----------|----------|------|------|
| 网络物理断开 | 高度怀疑被控 | 最彻底 | 可能丢失远程证据 |
| VLAN隔离 | 需保留网络访问 | 可远程操作 | 需要网络设备支持 |
| 防火墙ACL | 多系统协同隔离 | 灵活控制 | 可能被攻击者发现 |
| 端口禁用 | 特定服务隔离 | 精细控制 | 需确定端口 |

#### 2.3.3 长期遏制措施

**执行时间：遏制开始后4-24小时**

1. **修补攻击向量**
   - 安装补丁修复漏洞
   - 修改配置关闭攻击路径
   - 更新防火墙规则收紧访问

2. **收紧访问控制**
   - 重置所有相关账户密码
   - 撤销所有可疑的权限授予
   - 强制MFA重新认证
   - 检查并移除所有后门账户

3. **增强监控**
   - 在受影响区域部署额外监控
   - 设置新的告警规则（针对已发现攻击手法）
   - 增加日志采集范围和保留时长

4. **验证遏制效果**
   - 确认无新的恶意连接
   - 确认无新的异常账户/进程
   - 确认网络流量恢复正常

### 2.4 阶段四：根除（Eradication）

#### 2.4.1 根除目标

彻底消除攻击者在系统中的所有存在，包括：
- 恶意软件（病毒、木马、后门、挖矿程序）
- 持久化机制（注册表启动项、计划任务、服务、cron任务）
- 后门账户（隐藏账户、备用账户）
- 攻击工具和痕迹
- 攻击入口（漏洞、弱口令、配置缺陷）

#### 2.4.2 根除步骤

**步骤1：环境准备**
- 确认补丁已准备就绪
- 确认备份已可用（恢复演练）
- 准备干净的系统镜像

**步骤2：清除恶意软件**
- 全盘杀毒扫描（使用离线杀毒工具）
- 手动检查常见恶意软件位置
- 检查并清理浏览器插件和扩展
- 清理临时目录和下载目录

**步骤3：清除持久化机制**
- Windows检查项：
  - 注册表 Run/RunOnce 键
  - 计划任务（schtasks /query）
  - 服务（sc query）
  - WMI Event Subscriptions
  - 启动文件夹
  - 隐藏账户（lusrmgr.msc）
- Linux检查项：
  - cron.d, cron.daily, cron.hourly
  - systemd timers
  - init.d scripts
  - SSH authorized_keys
  - /etc/rc.local
  - ld.so.preload

**步骤4：重置凭证**
- 所有受影响系统的账户密码
- 服务账户和应用账户
- API密钥和Token
- SSL/TLS证书（如疑似泄露）

**步骤5：修补漏洞**
- 安装所有相关安全补丁
- 修改不安全配置
- 加强密码策略
- 收紧防火墙规则

**步骤6：全面扫描**
- 使用多个杀毒引擎扫描
- 使用YARA规则扫描已知恶意代码
- 检查是否还有残留IOC

### 2.5 阶段五：恢复（Recovery）

#### 2.5.1 恢复优先级

| 优先级 | 业务系统 | 恢复目标时间 |
|--------|----------|--------------|
| P0 | 核心业务系统（核心数据库、核心交易系统） | RTO ≤ 4小时 |
| P1 | 重要业务系统（内部办公、重要业务支撑） | RTO ≤ 24小时 |
| P2 | 一般业务系统（内部工具、辅助系统） | RTO ≤ 72小时 |
| P3 | 支撑系统（日志系统、监控平台） | RTO ≤ 7天 |

#### 2.5.2 恢复方式选择

| 方式 | 适用场景 | 优点 | 缺点 |
|------|----------|------|------|
| 从备份恢复 | 系统配置被破坏、数据被篡改 | 恢复可信状态 | 可能有数据丢失 |
| 重建系统 | 无法确认系统清洁 | 最彻底干净 | 耗时最长 |
| 清理后上线 | 确认已完全根除 | 平衡速度和安全 | 需要充分验证 |

#### 2.5.3 恢复流程

1. **恢复前验证**
   - 确认备份完整性（校验哈希）
   - 确认备份时间点（最后一次干净备份）
   - 测试恢复流程

2. **分阶段恢复**
   - Stage 1: 在隔离环境恢复并验证
   - Stage 2: 恢复至生产网络（仅安全团队可见）
   - Stage 3: 小范围用户测试
   - Stage 4: 全量恢复

3. **恢复后验证**
   - 系统完整性检查（文件哈希）
   - 端口和服务检查
   - 账户和权限检查
   - 业务功能测试
   - 安全基线验证

4. **72小时加强监控**
   - 恢复后72小时内加强监控
   - 设置更敏感的告警阈值
   - 实时监控异常指标

### 2.6 阶段六：事后活动（Post-Incident）

#### 2.6.1 事件复盘

**复盘会议要求：**
- 参加人员：应急响应团队全体、安全负责人、受影响业务负责人
- 时间要求：事件关闭后14天内
- 会议时长：2-4小时

**复盘内容：**

1. **时间线重建**
   - 精确到分钟的事件时间线
   - 每个阶段持续时间
   - 各团队响应时效

2. **响应评估**
   - 是否遵循既定流程
   - 流程是否有效
   - 沟通是否顺畅
   - 决策是否正确

3. **根因分析（5 Whys方法）**

   ```
   示例：
   Q: 为什么发生数据泄露？
   A: 因为攻击者获得了域管理员权限。
   Q: 为什么攻击者能获得域管理员权限？
   A: 因为某台服务器被植入后门，攻击者通过它横向移动。
   Q: 为什么那台服务器被植入后门？
   A: 因为员工点击了钓鱼邮件中的链接。
   Q: 为什么员工会点击钓鱼邮件？
   A: 因为钓鱼邮件伪装得很好，且员工安全意识培训不足。
   Q: 为什么安全意识培训不足？
   A: 因为培训频率低，且未针对钓鱼场景进行专项演练。
   → 根因：安全意识培训体系不完善
   ```

4. **改进项识别**

   | 类别 | 具体改进项 | 负责人 | 完成时限 |
   |------|------------|--------|----------|
   | 流程 | 完善遏制决策流程 | 安全负责人 | 30天 |
   | 技术 | 部署邮件钓鱼检测 | 网络安全工程师 | 60天 |
   | 培训 | 增加钓鱼演练频率 | 安全运营负责人 | 45天 |
   | 工具 | 完善内存取证工具包 | 安全分析师 | 30天 |

#### 2.6.2 文档归档

**归档内容：**
- 完整事件时间线
- 所有分析报告
- 所有沟通记录
- 所有决策记录
- 证据清单和存放位置
- 复盘会议记录
- 改进项跟踪表

**归档要求：**
- 至少保留7年
- 敏感信息加密存储
- 设置访问权限

## 3. 常见事件处置指引

### 3.1 勒索软件处置

**特殊注意事项：**
- 确认勒索软件家族（用于判断是否有解密工具）
- 不要急于支付赎金
- 隔离过程注意避免触发加密锁死

**处置流程：**
1. 立即物理隔离（断网）
2. 禁用所有网络共享
3. 确认勒索信息（截图保存）
4. 评估备份可用性
5. 确认感染范围
6. 如有解密工具，先恢复非关键系统
7. 无法恢复则重建系统
8. 恢复后72小时加强监控

### 3.2 数据泄露处置

**首要任务：**
1. 确认数据泄露事实
2. 评估泄露范围和数量
3. 立即阻断泄露渠道
4. 评估监管通知义务

**通知决策：**

| 数据类型 | 数量 | 通知对象 | 时限 |
|----------|------|----------|------|
| 个人信息（GDPR） | ≥1人 | 监管机构+受影响个人 | 72小时 |
| 个人信息（国内） | ≥100人 | 网信办 | 72小时 |
| 重要数据 | 任意 | 等保办 | 72小时 |
| 客户金融数据 | 任意 | 金融监管机构 | 立即 |

### 3.3 账户被盗处置

**处置流程：**
1. 立即禁用被入侵账户
2. 清除该账户所有会话
3. 重置该账户及关联账户密码
4. 检查该账户的所有操作日志
5. 检查是否创建了后门账户
6. 检查是否发生了横向移动
7. 通知相关人员
8. 如为特权账户，评估是否需要全网凭证重置
