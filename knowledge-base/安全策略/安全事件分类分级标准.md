# 安全事件分类分级标准

## 1. 事件分类

根据 NIST SP 800-61r2 和国内行业标准，将安全事件分为以下类别：

### 1.1 恶意代码类（M）

| 代码 | 类别 | 示例 |
|------|------|------|
| M1 | 病毒/蠕虫 | 传统病毒、宏病毒、引导区病毒 |
| M2 | 木马/后门 | 远控木马、键盘记录器、Rootkit |
| M3 | 勒索软件 | 文件加密勒索、网络勒索 |
| M4 | 间谍软件 | 广告软件、监控软件、间谍工具 |
| M5 | 挖矿软件 | 加密货币挖矿程序 |
| M6 | 僵尸网络 | C2通信、傀儡主机 |

### 1.2 未授权访问类（UA）

| 代码 | 类别 | 示例 |
|------|------|------|
| UA1 | 账户入侵 | 弱口令破解、凭证盗取、社工钓鱼 |
| UA2 | 权限提升 | 本地提权、域提权、容器逃逸 |
| UA3 | 横向移动 | RDP/SMB横向、Pass-the-Hash |
| UA4 | 物理入侵 | 设备丢失、未授权接入 |

### 1.3 拒绝服务类（DE）

| 代码 | 类别 | 示例 |
|------|------|------|
| DE1 | 网络DoS | SYN Flood、UDP Flood、ICMP Flood |
| DE2 | 应用DoS | HTTP Flood、CC攻击、API滥用 |
| DE3 | 分布式DoS | 反射放大攻击、僵尸网络攻击 |
| DE4 | 资源耗尽 | 磁盘占满、内存耗尽、进程fork炸弹 |

### 1.4 违规使用类（IU）

| 代码 | 类别 | 示例 |
|------|------|------|
| IU1 | 策略违反 | 安装未授权软件、访问禁止网站 |
| IU2 | 配置不当 | 安全配置弱化、端口违规开放 |
| IU3 | 数据泄露 | 敏感数据外发、打印违规文件 |

### 1.5 数据泄露类（DX）

| 代码 | 类别 | 示例 |
|------|------|------|
| DX1 | 主动外泄 | 主动向外部传输敏感数据 |
| DX2 | 被动泄露 | 配置错误导致数据暴露 |
| DX3 | 数据库泄露 | SQL注入、拖库攻击 |
| DX4 | 文件泄露 | 文档意外分发、邮件错发 |

### 1.6 内部威胁类（IT）

| 代码 | 类别 | 示例 |
|------|------|------|
| IT1 | 恶意内部人员 | 主动破坏、窃取数据、报复性行为 |
| IT2 | 疏忽行为 | 钓鱼中招、丢失设备、违规操作 |
| IT3 | 供应链威胁 | 第三方人员违规、内部人员被策反 |

### 1.7 社会工程类（SC）

| 代码 | 类别 | 示例 |
|------|------|------|
| SC1 | 钓鱼邮件 | 鱼叉式钓鱼、BEC商业邮件诈骗 |
| SC2 | 电话诈骗 | 冒充IT支持、冒充领导 |
| SC3 | 物理社工 | 尾随进门、冒充访客 |

### 1.8 硬件/物理类（HW）

| 代码 | 类别 | 示例 |
|------|------|------|
| HW1 | 设备丢失/被盗 | 笔记本丢失、U盘丢失 |
| HW2 | 硬件篡改 | 键盘记录器植入、网线嗅探 |
| HW3 | 环境威胁 | 断电、火灾、空调故障 |

## 2. 事件分级

### 2.1 分级原则

事件分级基于以下三个维度：

1. **业务影响**：对核心业务的影响程度
2. **数据影响**：涉及数据的敏感程度和数量
3. **恢复难度**：恢复正常运营的复杂度

### 2.2 分级标准

| 级别 | 名称 | 定义 | 响应时间 | 示例 |
|------|------|------|----------|------|
| **P0** | 紧急 | 核心业务系统瘫痪或重大数据泄露，需立即处置 | 立即（5分钟内响应） | 勒索软件加密核心数据库、大规模数据泄露（>10000条）、APT在核心网络活跃 |
| **P1** | 高危 | 重要业务系统受影响或敏感数据面临风险，需紧急处置 | 15分钟内响应 | 域控制器被入侵、重要系统被植入后门、内部人员窃取数据 |
| **P2** | 中危 | 局部系统受影响，有一定风险，需及时处置 | 1小时内响应 | 单台服务器被入侵、钓鱼攻击导致部分账户泄露 |
| **P3** | 低危 | 系统存在安全隐患但未造成实际影响 | 4小时内响应 | 扫描探测行为、弱口令尝试、异常登录（已拦截） |
| **P4** | 提示 | 潜在风险或已消除的告警事件 | 24小时内分析 | 误报确认、安全策略测试结果 |

### 2.3 分级调整规则

**应当升级的情况：**
- 影响范围超出初步评估（如单系统→多系统）
- 发现持久化机制（后门、计划任务、隐藏账户）
- 涉及高权限账户（域管理员、IT管理员）
- 数据确认已外泄
- 攻击者仍在活跃
- 监管要求触发（等保合规事件报告要求）

**可以降级的情况：**
- 确认为误报（经完整调查）
- 影响范围明确且已完全遏制
- 已确认无数据泄露

## 3. 事件报告要求

### 3.1 内部报告

| 级别 | 报告对象 | 报告时限 |
|------|----------|----------|
| P0 | CISO + CIO + CEO + 法务 + 公关 + 董事会 | 立即口头通知，1小时内书面 |
| P1 | CISO + CIO + 业务负责人 + 法务 | 1小时内通知 |
| P2 | 安全运营负责人 + IT运维 + 业务部门 | 4小时内通知 |
| P3 | 安全运营团队 | 每日简报 |
| P4 | 安全运营团队 | 每周汇总 |

### 3.2 外部报告

| 触发条件 | 报告对象 | 报告时限 |
|----------|----------|----------|
| 个人信息泄露≥100人 | 网信办 | 知道之日起72小时内 |
| 重要数据泄露 | 等保办 | 知道之日起72小时内 |
| 关键信息基础设施事件 | 网信办 + 行业监管部门 | 立即报告，24小时内书面 |
| 涉及执法 | 公安机关 | 立即配合 |

## 4. 事件关联分析

### 4.1 事件关联规则

多个低级别事件同时出现时，应评估是否构成高级别事件：

| 关联特征 | 建议升级 |
|----------|----------|
| 同一源IP对多个目标发起攻击 | P2→P1 |
| 同一账户在短时间异常登录多台主机 | P3→P2 |
| 扫描行为后紧跟漏洞利用尝试 | P3→P1 |
| 内部钓鱼成功后紧跟权限提升 | P2→P1 |
| 勒索软件告警 + 文件加密行为 | 直接定级P0 |

### 4.2 攻击链分析

使用 Kill Chain 模型评估攻击进展阶段：

1. **侦察（Reconnaissance）** — 扫描、探测、信息收集
2. **武器化（Weaponization）** — 制作攻击载荷
3. **投递（Delivery）** — 邮件、网站、U盘等投递
4. **利用（Exploitation）** — 漏洞利用、恶意代码执行
5. **安装（Installation）** — 后门安装、持久化
6. **命令控制（C2）** — 与攻击者建立通信
7. **目标达成（Action）** — 数据窃取、破坏、勒索

*参考标准：NIST SP 800-61r2、GB/T 24363-2009、招商局集团网络安全事件管理办法*
