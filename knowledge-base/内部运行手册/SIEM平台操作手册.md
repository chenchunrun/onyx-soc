# SIEM平台操作手册

## 平台信息

- 平台名称：安全告警检索平台
- 接入方式：通过 `search_security_alerts` 工具或平台原生控制台
- 当前用途：检索告警、补充时间线、定位受影响主机/账号、为工单与升级提供证据
- 对应自动化能力：`search_security_alerts`、`send_security_alert`

## 常用场景

- 按告警编号查事件
- 按用户名查登录行为
- 按主机查异常进程、异常连接、异常认证
- 按 IP / 域名 / URL 查关联日志
- 钓鱼、账号失陷、横向移动、异常外联的首轮研判

## 常用字段映射

- 用户字段：`user`、`username`、`account`、`email`
- 主机字段：`hostname`、`device_name`、`asset_name`
- IP 字段：`src_ip`、`dst_ip`、`client_ip`
- 时间字段：`timestamp`、`event_time`、`ingest_time`
- 告警字段：`alert_id`、`alert_name`、`severity`、`category`

## 字段映射示例

| 分析目标 | 常见字段 | 说明 |
| --- | --- | --- |
| 用户身份 | `user` / `email` | 用于关联登录、邮件、权限变更 |
| 主机定位 | `hostname` / `device_name` | 用于串联终端、EDR、资产平台 |
| 网络定位 | `src_ip` / `dst_ip` | 用于识别异常外联、横向移动 |
| 时间对齐 | `event_time` / `ingest_time` | 用于区分事件发生和日志进入平台的时间 |
| 风险判断 | `severity` / `category` | 用于分级和工单优先级判断 |

## 首轮排查动作

1. 用告警编号或主机名确认是否为单点事件还是一组关联事件。
2. 看触发时间前后 30 分钟内是否有登录、进程、网络、策略变更。
3. 看同一账号、同一主机、同一源 IP 是否还有其他高危告警。
4. 看是否已经命中已知白名单、维护窗口或已备案变更。
5. 输出第一版结论：误报、待观察、需要立案、需要立即升级。

## 常用查询模板

### 账号失陷调查

- 过滤条件：`user=<账号>` + 最近 24 小时
- 重点观察：异地登录、失败后成功、MFA 变化、权限提升、邮件规则变更

### 主机失陷调查

- 过滤条件：`hostname=<主机>` + 最近 24 小时
- 重点观察：可疑进程树、脚本执行、异常出网、远程执行、服务创建

### 钓鱼点击调查

- 过滤条件：`email=<用户>`、`url/domain=<钓鱼域名>`、最近 48 小时
- 重点观察：点击后是否出现下载、脚本执行、凭证输入、异常登录

### 横向移动调查

- 过滤条件：同一账号或同一源主机，最近 6 小时
- 重点观察：RDP、SMB、WinRM、PsExec、远程服务创建

### 数据外传调查

- 过滤条件：`hostname=<主机>` 或 `user=<账号>`
- 重点观察：异常外联、云盘上传、压缩打包、批量读取、夜间传输

## 查询使用建议

- 首先按时间窗限制到 15 分钟、1 小时或 24 小时
- 先固定一个主键：用户、主机、IP、告警编号中的一个
- 遇到多源数据时先对齐时间和命名口径
- 先做证据串联，再决定是否升级或立案

## 日常运维要点

- 入数健康检查：确认关键日志源持续入数
- Parser / Pipeline 异常检查：确认字段没有大面积空值或错位
- 告警延迟检查：确认告警生成与入库时间差在可接受范围
- 存储与保留策略检查：确认热数据与归档策略符合调查需求
- 白名单与抑制规则检查：避免长期噪声把真实高危事件淹没

## 与安全自动化的关系

- `search_security_alerts`：用于告警检索与首轮调查
- `send_security_alert`：用于把确认后的高优先级事件发到通知链路
- `create_security_ticket`：用于把调查结论转成工单

## 常见问题

- 无日志：先确认日志源、采集链路、租户/索引选择是否正确
- 字段解析错误：优先检查 Parser、Pipeline、字段映射版本
- 时间错位：优先核对时区、NTP、事件时间与入库时间
- 告警重复触发：检查聚合窗口、抑制条件、规则去重键
- 查到了告警但证据不足：补查 EDR、邮件、身份、资产平台
