# 告警分级标准

## 目标

- 统一不同平台告警的优先级口径
- 支撑值班分流、升级决策、SLA 管理

## 建议分级

### P1 / Critical

- 已确认主机失陷、横向移动、勒索、数据外传
- 核心身份系统或关键业务系统被接管
- 高权限账号被确认滥用
- 已需要立即隔离、封禁、下线或应急通报

### P2 / High

- 高可信恶意行为，尚未确认最终影响
- 多源告警形成完整攻击链
- 关键资产上出现高风险 IOC / TTP
- 存在扩大影响的明显风险

### P3 / Medium

- 单点异常，需要进一步调查
- 可疑登录、可疑进程、可疑网络连接
- 存在一定误报可能，但不能直接忽略
- 暂无高危后续动作证据

### P4 / Low

- 低可信弱信号
- 已知噪声模式
- 基线偏差但无明显攻击证据
- 已有较强误报依据

## 分级参考维度

- 资产重要性
- 身份权限级别
- 攻击链阶段
- 证据强度
- 横向移动可能性
- 业务影响
- 数据影响

## 升级条件

- 新增高权限账号迹象
- 新增横向移动或持久化证据
- 新增数据访问或导出证据
- 影响资产从普通资产升级到关键资产

## 响应时限建议

- `P1`：立即响应，尽快升级到负责人
- `P2`：30 分钟内开始调查并形成初步结论
- `P3`：当班内处理并判断是否需要升级
- `P4`：纳入日常排队或规则优化

## 定级示例

- 钓鱼邮件点击后触发脚本执行并出现异常登录：至少 `P2`，如确认主机落地恶意程序升为 `P1`
- 普通办公终端单点可疑 PowerShell，但无后续外联：通常 `P3`
- 已知扫描器、已备案变更触发的弱信号：通常 `P4`
- 域管账号在非常用地点成功登录并创建新高权账户：直接 `P1`

## 事件类型速查

| 事件类型 | 常见初始等级 | 升级条件 |
| --- | --- | --- |
| 钓鱼点击 | `P3/P2` | 出现脚本执行、异常登录、恶意下载 |
| 账号失陷 | `P2` | 涉及高权账号、跨系统扩散、批量异常行为 |
| 勒索迹象 | `P1` | 出现加密、批量改名、停用安全工具 |
| 横向移动 | `P2` | 涉及关键资产、高权限账号、批量远程执行 |
| 数据外传 | `P2` | 涉及敏感数据、大体量导出、对外通报风险 |
| 基线偏差 | `P4/P3` | 出现真实攻击链证据时升级 |

## 输出建议

- 当前等级
- 分级依据
- 是否升级
- 需要的响应时限
