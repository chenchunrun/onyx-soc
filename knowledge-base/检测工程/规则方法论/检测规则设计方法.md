# 检测规则设计方法

## 1. 目标

用于指导检测规则从“想法”变成“可落地、可维护、可调优”的规则。

## 2. 检测规则的基本结构

- 检测目标
- 对应 ATT&CK 战术/技术
- 触发条件
- 需要的数据源
- 排除条件
- 风险等级
- 误报来源
- 处置建议

## 3. 设计流程

### 3.1 定义目标行为

- 攻击者在做什么
- 行为发生在哪个资产、账号、系统上
- 这类行为为何值得检测

### 3.2 找到可观察信号

- 进程
- 登录
- 网络连接
- 文件写入
- 注册表
- 邮件行为
- API 调用

### 3.3 明确数据源

- Windows Event
- Linux Audit / Syslog
- EDR
- Proxy
- DNS
- Email Gateway
- Cloud Audit

### 3.4 定义规则条件

- 需要哪些字段
- 如何减少误报
- 是否需要关联多个事件
- 是否需要阈值、时间窗、基线

### 3.5 定义上下文

- 关联用户
- 关联主机
- 关联资产重要性
- 关联是否是管理账号或关键系统

## 4. 常见规则类型

- 单事件高置信规则
- 多事件关联规则
- 阈值型规则
- 基线偏离规则
- 序列型攻击链规则

## 5. 误报控制原则

- 优先缩小目标面
- 增加白名单和例外条件
- 引入资产、用户、时间、环境上下文
- 不要把“高频正常行为”直接做成高危告警

## 6. 输出格式建议

每条规则至少应包含：

- 名称
- 目的
- 数据源
- ATT&CK 技术
- 查询逻辑
- 排除逻辑
- 告警等级
- 调查建议
- 处置建议
